# Kain

**A price-optimized nutrition engine for Filipino families.**

Enactus Philippines 2026, National Competition — Early-Stage Project Track.
Angeles University Foundation.

---

## What it does

Kain is a browser-based, offline-capable Progressive Web App. A family enters a
food budget and household size; Kain checks every combination of local recipes
and returns the single most nutritious meal plan that fits — not just an
affordable one, the *optimal* one — along with an exact shopping list and a
chart showing how much of the family's daily nutritional need the plan covers.

Everything above runs as a client-side calculation in the browser, with no
server involved and no network required after the first load.

## Why it exists

Food inflation for the poorest 30% of Filipino households more than doubled in
a single month in early 2026, and child stunting rose for the first time in a
decade. Recipe content ignores real prices; budgeting apps ignore nutrition.
Kain sits in the gap: a fixed budget in, a specific, locally-priced, nutritious
plan out.

## Quick start

No dependencies, no build step, no bundler.

```bash
npm test          # runs the test suite (node --test)
npm run serve     # serves the app at http://localhost:8000
npm run build:data  # regenerates data/recipes.json from its price/recipe sources
```

Open `http://localhost:8000`, enter a budget and family size, and Kain solves
for a plan. Try it offline too: load the page once, then disconnect and reload
— the full flow still works.

## Project structure

```
index.html, sw.js, manifest.webmanifest   the app shell (PWA, offline cache)
js/
  solver.js            core bounded-knapsack DP solver — pure, zero network calls
  nutrition-targets.js daily nutrition targets (FNRI RENI), data only
  nutrition.js         coverage: how much of daily need a plan delivers
  shopping-list.js      merges a plan into one priced shopping list
  app-state.js         input -> calculating -> results screen state machine
  app.js               DOM adapter — renders state, no business logic
  format.js            display formatting (pesos, quantities, chart bars)
data/
  prices.json           ingredient prices — hand-edited source of truth
  recipes.source.json   recipe quantities and nutrition — hand-edited source
  recipes.json           GENERATED by scripts/build-data.mjs — do not edit directly
scripts/build-data.mjs  derives data/recipes.json from the two sources above
test/                   node --test suite (55 tests, zero test-framework deps)
```

## Tech stack

| Layer | Choice | Why |
|---|---|---|
| Structure/logic | Vanilla JS (ES modules) | No framework needed; keeps the PWA bundle small for low-end phones |
| Styling | Tailwind CSS (CDN) | No build step during a time-constrained sprint |
| Charts | Chart.js (CDN) | Nutrition coverage visualization |
| Core solver | Vanilla JS, bounded knapsack DP | Genuinely optimal, not just fast — defensible under technical scrutiny |
| Data | Static JSON, generated | See `data/` above; keeps the app static-hostable |
| Offline | Web App Manifest + Service Worker | Works on weak/unreliable signal, common in the communities this targets |

The core solver is a hard architectural constraint: it and everything it
imports must make zero network calls. This is enforced by a test
(`test/offline-shell.test.js`) and is the basis of the project's Innovation and
Scale claims.
